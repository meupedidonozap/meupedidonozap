- DiColore attendance uses period-bounded details and invoker historical summaries with cached portfolio reads; other stores keep the legacy panel to avoid cross-tenant behavior changes.
- DiColore client intelligence defaults to 60 days and uses invoker invoice summaries bounded to the selected and preceding equal interval; label history/frequency with those bounds and never infer lifetime inactivity from missing period data. Load item summaries only on the products tab through a single compact invoker aggregation before catalog joins, so repeated pagination and mix failures cannot block portfolio reports; invoice RLS and configuration remain store-scoped.
- Analytics exports load spreadsheet/PDF libraries on demand so opening reports does not load export dependencies.
- TitlesPanel delivers authorized boleto bytes through the shared PDF delivery function in download mode: DiColore Android opens the local preview with native save/share, while browsers keep direct downloads, avoiding blocked WebView blob links without regenerating bank documents.
- DiColore geographic intelligence reuses scoped lifecycle data and lazy Leaflet/Supercluster; municipal fallback is explicitly approximate, sourced from bundled IBGE-derived kelvins/municipios-brasileiros references, never external customer-address geocoding.
- Client lifecycle loads a separate invoker purchase-day summary only when selected, bounded to 24 months with invoice RLS; observed first/absent purchases never imply lifetime acquisition/inactivity. Lifecycle filters and exports share the same scope and use the selected end date for recency.
- DiColore checkout keeps the saved-order WhatsApp step in its own dialog: the cart is cleared once the order is stored, the link is a plain universal WhatsApp link, and leaving requires an explicit abort answer; a tested foreground watcher raises that question when WhatsApp never opened. Other stores keep the legacy dialog.
- Store install entry points (APK link, browser shortcut, iOS guide) live in one block on the login gate, chosen by a tested resolver and scoped by store slug; it adds no service worker of its own, so other stores keep their behavior. A store whose home-screen shortcut must open on it ships a real same-origin manifest plus an early index.html slug check that repoints manifest and canonical before the app loads, because iOS ignores in-memory manifests. The APK is a hosted asset pointer linked by absolute hosted URL, since the custom domain does not serve the asset route; an https .apk URL in store settings overrides it.
